# ADR-0002：设置面板尺寸三模式

## 背景

要替代的旧方案只有一种行为：宽窗口撑到 1360×1000，小窗口铺满。它不能按屏幕调整，也没有 UI。新需求要“调节设置窗口的宽度、高度”，同时不能把简单需求做成参数迷宫。

DSH 设置面板的原生尺寸是 800×800，外层约束是 `max-width: calc(100vw - 48px)`、`max-height: min(800px, 100vh - 2·max(24px, overlayTop))`，移动端（`< 768px`）另有铺满布局。

## 决策

采用三种模式，而不是一堆独立参数：

| 模式 | 语义 | 尺寸 |
| --- | --- | --- |
| `default` | 不接管，完全交给 shell | 不注入样式 |
| `full` | 铺满可用区域，保留边距 | `w = 100vw - 2·margin`；`h = 100vh - 2·max(margin, overlayTop)` |
| `custom` | 指定宽高，超出视口时收缩 | `w = min(width, 100vw - 2·margin)`；`h = min(height, 100vh - 2·max(margin, overlayTop))` |

配套决定：

1. **边距是三模式共用的一个值**（0–64，默认 24），不做上下左右独立——v1 保持简单，按边独立留到 v2。
2. **垂直方向要避开框架安全区**：`gapY = max(margin, overlayTop)`，其中 `overlayTop` 来自 `--dsh-frame-overlay-top`（macOS 交通灯）。这样 `margin: 0` 时横向可以贴边，顶部仍不会钻到标题栏下面。
3. **移动端不接管**：`@media (width <= 767px)` 内不生成尺寸规则，避免破坏 shell 的铺满 + 横向导航布局。
4. **首装默认值 `custom / 1360×1000 / margin 24`**，与旧方案观感一致，替换无回归；“恢复默认”回到这组值，想恢复原生需显式选 `default`。
5. **数值范围**：宽 640–1920，高 480–1440，边距 0–64；`full` 模式不受宽高上限影响。
6. **CSS 覆盖必须 `!important`**：shell 规则同元素同特异性，且注入顺序不可控；同时把 `max-width` / `max-height` 置为 `none`，否则 shell 的上限会压过自定尺寸。

> 待评审：首装默认是否应改为 `default`（完全不接管），把“变大”变成用户显式选择。实现上只需改 `DEFAULT_SETTINGS_PANEL`。

## 后果

正面：

- 三种模式覆盖“原生 / 铺满 / 精确”三类诉求，参数只有 4 个；
- 小窗口不再需要旧插件的 1200×820 断点：`min()` 连续收缩，行为更可预测；
- 移动端零风险；
- 默认值与旧插件等价，迁移无感。

负面：

- `full` 与 `custom` 在“请求值恰好等于视口减边距”时视觉相同，模式差异只在语义和默认控件上；
- 边距统一值不能做“上窄下宽”这类非对称布局；
- 仍依赖 `data-shortcut-modal` 标记，未来 shell 改标记需要适配。

## 备选方案

| 方案 | 为什么不选 |
| --- | --- |
| 只做宽高两个数字（无模式） | 无法表达“跟随原生”；小窗口要用户自己算 |
| 保留旧的 1200×820 断点 | 与自定义宽度冲突，规则难解释；`min()` 已能连续覆盖 |
| 固定几档预设（小/中/大/全屏） | 灵活度不足，用户仍会要精确值 |
| 按边独立边距（4 个值） | v1 过度设计，UI 复杂度翻倍 |
| 用 JS 监听尺寸并设 inline style | 依赖面板节点生命周期，易被 React 重渲染覆盖；CSS 方案更稳 |
