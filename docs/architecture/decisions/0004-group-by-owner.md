## 背景

0.1.x 的「界面调整」只有一个 tweak（设置窗口尺寸），页面把字段平铺成一列，尚可接受。但 tweakit 的定位是「承载多个界面 tweak 的容器」，一旦加第二个 tweak，就会出现两个问题：

1. **信息架构缺失**：卡片上下串联，模块之间没有导航，用户要滚过整页才能找到后面的 tweak。
2. **没有归属概念**：tweak 改的是 DSH 本体或某个插件的界面，但页面上表达不出「这一项属于谁、管的是哪块」。后续适配 better-sidebar、ds-bot 等插件时，所有可调项会混在一列。

因此需要一个稳定的上层分组，并明确它与「插件发现/注册」的关系——后者决定这是展示层改动，还是要先造一套跨插件协议。

## 决策

### 1. 三级概念：`group` → `tweak` → `field`

- **group**：按**归属**划分，即「这个 tweak 调的是谁的界面」。DSH 本体用 `dsh`，其它插件用目标插件标识（如 `better-sidebar`）。
- **tweak**：一个可独立配置的界面模块，拥有自己的偏好切片、descriptor 与字段。
- **field**：tweak 内的一个可编辑项。

不用 `section` 作为第一级：DSH 的 `settings.section` 槽与组件 `TweakitSection` 已占用该词，且 section 不表达归属。

### 2. 分组是静态的展示元数据

`TWEAK_GROUPS` 写在 `src/shared/prefs.ts`，`TweakUi.group` 必填，`TweakGroupId` 由 `TWEAK_GROUPS` 派生为闭集，归属写错即编译错误；运行期由 `groupOfTweak` 兜底到 `other`。

分组**不进入持久化契约**：wire 字段、默认值、`PREFS_VERSION`、迁移路径都不变。

### 3. 布局采用左侧两级折叠树（B 方案）

左侧单栏：组头淡化、可折叠，模块条目是导航主体；右侧只渲染当前 tweak 的字段。手风琴（同时只展开一组），组数 = 1 时省略组头；页面变窄时降级为分组下拉 + 横向 chip。细节与验收标准见[需求设计](../../features/2026-11-09-tweak-grouping.md)。

### 4. 本期不提供运行时注册 API

第三方插件不能调用 `ctx.tweakit.registerTweak(...)` 注入分组或 tweak。适配其它插件的方式是**改 tweakit 源码、按目标插件建组、发版**。

只保留形状：组 id 用目标插件标识、`TweakUi.group` 必填、注册表是纯数据，未来可以增量合并。

## 理由

1. **其它插件不会为配置去依赖 tweakit**。它们要做可调项，第一选择是 DSH 自己的 settings / `configForms`；tweakit 目前没有提供比宿主更省事的能力。
2. **运行时注册会把不稳定的存储形状固化成公开 API**。跨插件写别人的 settings entry 不成立：字段必须在宿主 schema 里预声明，tweakit 的 entry 只属于自己。
3. **只有当 tweakit 的 UI 与存储成为事实标准时，注册接口才有价值**。现在开放，等于用一个没人用的 API 换走后续改设计的自由。
4. **分组本身是展示层问题**。按归属分组、静态声明就能解决「平铺 + 无归属」，不需要先造协议。

## 备选方案

| 方案 | 做法 | 不采用的原因 |
| --- | --- | --- |
| A 维持平铺 | 继续纵向堆卡片，加锚点/搜索 | 模块多了没有导航；归属仍然表达不出来 |
| B 顶部横向切组 + 组内竖向 tab（原 v1） | 组在顶部，模块在左侧 | 与设置弹窗外层导航叠加，横向占位大；组多时顶部拥挤 |
| **C 左侧两级折叠树（采纳）** | 组头淡化可折叠，模块缩进，右侧单 tweak | 与 shell 的左侧导航方向一致，纵向扩展性最好 |
| D 三级以上树 | 组 → 子组 → tweak | 当前只有两级归属，多一层是无依据的抽象 |
| E 运行时注册服务 | `ctx.tweakit.registerTweak` + 动态注册表 | 见「理由」：契约过早、跨插件存储无解 |

## 后果

**正面**

- 新增 tweak 只需在 `prefs.ts` 声明归属与字段，导航代码零改动。
- 归属写错在编译期暴露；组数 = 1 时观感与 0.1.x 基本一致，不倒退。
- 已安装用户升级后配置值不变，无迁移、无 reset，可安全回滚到 0.1.x。

**负面与缓解**

- 适配新插件仍需改源码发版 → 在文档中明确这是当前定位；等真实需求出现再评估注册。
- 折叠可能让配置「藏起来」→ 组头显示模块数、默认展开当前组、折叠当前组时内容保留并留强调线。
- 两层竖排导航（shell 外层 + 本页内层）视觉变量增加 → 组头淡化、模块为主体，M1 先出截图评审。

**重新评估的触发条件**

- 有 2 个以上第三方插件明确要求贡献 tweak，且愿意接受 tweakit 的存储形状；
- DSH 官方出现插件级设置页/设置分组的平台能力，tweakit 可改为适配而非自建；
- settings 服务对大 JSON 字段的支持被验证，跨插件统一存储变得可行。
